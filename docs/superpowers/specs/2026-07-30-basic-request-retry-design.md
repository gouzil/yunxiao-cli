# 基础请求重试设计

## 目标

降低 `repo list`、`commit list` 等只读命令因临时 `EOF`、连接中断、限流或服务端故障而失败的概率。

## 方案

复用 `internal/api.Client.Do` 现有重试循环，不新增依赖或传输层包装：

- 生产客户端启用最多 2 次额外重试，共最多 3 次请求。
- 仅自动重试 `GET` 和 `HEAD`；写请求保持单次执行，避免重复创建或修改。
- 可重试错误包括 HTTP 429、HTTP 5xx，以及 `EOF`、意外 `EOF`、超时和连接中断等网络错误。
- 其他错误立即返回。
- 两次等待沿用现有线性退避：250ms、500ms。
- 等待期间响应 `context` 取消或超时并立即退出。

请求仍从各业务服务汇聚到 `Client.Do`，因此无需逐命令修改。

## 验证

在 `internal/api/client_test.go` 使用真实 `httptest` 服务验证：

- `GET` 前两次断开连接并返回 `EOF`，第三次成功，客户端最终返回成功。
- `POST` 遇到相同错误只请求一次并返回错误。

运行 API 包测试和全量 Go 测试，确认现有行为未回归。

## 非目标

不增加命令行重试参数、随机抖动、`Retry-After` 解析、写请求幂等键或第三方重试库；出现实际需求后再扩展。
